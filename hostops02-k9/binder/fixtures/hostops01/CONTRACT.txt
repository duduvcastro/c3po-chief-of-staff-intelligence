3.7 Envelope. The transport fixes three status strings; the meaning is in "outcome".
  exit 0  METADATA_ONLY_REQUIRES_REVIEW      KNOWN_COMPLETE   only the operation's success outcome
  exit 2  PARTIAL_METADATA_REQUIRES_REVIEW   KNOWN_PARTIAL    a read-only run that is incomplete or found a mismatch;
                                                              a write run that changed something and did not finish
  exit 1  REFUSED                            KNOWN_REFUSAL    nothing was observed (read-only) / no mutating call
                                                              succeeded and none is uncertain (write). The receipt
                                                              may carry the precheck table that names what exists.
  exit 3  (anything that escapes run())      UNCERTAIN        state unknown; established only by a read-only
                                                              operation under its own GO
Sources return every refusal as an object and never raise out of run(). The launcher enters the payload with exit
code 3, so an exception that escapes run() anyway is filed UNCERTAIN by the unchanged transport and can never be
read as "refused, nothing happened" (tested with real processes for KeyError, a code-looking ValueError, a non-dict
result). Inside the sources every mutating call goes through one function: gate, count, call. A call that failed
with an OS error changed nothing (mkdir, exclusive open, link and unlink are atomic); a call that was issued and
never settled is uncertain. REFUSED is returned only while nothing succeeded and nothing is uncertain; the last
resort handler of run() applies the same rule to any exception, KeyboardInterrupt included.
A refusal receipt of a write operation carries its own request, GO and payload hashes and metadata_sha256; the
dispatcher does not bind refusals, so they are verified by command when filed. Any remote result consumes the GO.
A write that outlives its transport: the watchdog kills the local SSH client, not the remote process. The local
result is then UNCERTAIN, the GO is spent, and the state is established by OP_PRECHECK or OP_READBACK under its own
GO, never by a second attempt.

3.9 Pinned parents. An existing directory is never assumed: every component from "/" is a signed row
{path, device, inode, uid, gid, mode} copied from a read-only receipt. The walk opens "/" and each component by
dir_fd with O_NOFOLLOW; an lstat classifies the component first (missing, symbolic link, not a directory), and the
held descriptor must equal the row on all five values, mode on all twelve bits. Before each creation the path is
walked again and must still lead to the descriptor held. In code, and not left to the signers:
  - outside the data volume every component must be root-owned and not writable by group or other
    (CHAIN_ROW_UNSAFE); at and below the data volume root the observed owner and mode are accepted as signed, with
    one floor: a row writable by others without the sticky bit is refused (CHAIN_ROW_WORLD_WRITABLE), because any
    local user could then rename the root-owned directory this run creates. 1000:1000 0755 (the host, HOSTFACTS_01),
    0775 and 1777 are accepted;
  - a directory that receives a new entry must not be setgid (PARENT_SETGID): the kernel would hand its group and
    the bit to the child, and nothing in this family could then remove the result;
  - a parameterised path (data volume, capacity root) is never one of the fixed directories of this family nor a
    directory above one (/etc, /etc/systemd/system, /var/lib, /etc/c3po-bar, /var/lib/c3po-bar, /etc/c3po-reader,
    /var/lib/c3po-reader): naming /var or /var/lib as the data volume would lift the floor from the chain the fixed
    layout hangs from (PATH_FORBIDDEN_ZONE). The composed path <data volume>/<leaf> is checked against the
    forbidden zones as well, not only its two halves.
Whether the data volume root is a mount point is not refused in code (a volume that is not mounted has other rows
than the signed ones, PARENT_IDENTITY_MISMATCH); it is shown literally: effects.data_volume_root
.device_differs_from_parent, and mount_point_by_device_change in the precheck notes.
The boot identifier: every write request and every gate readback names the SHA-256 of the boot identifier of its
evidence. A different boot refuses before any effect (EVIDENCE_FROM_EARLIER_BOOT), because device numbers may be
renumbered by a reboot. OP_PRECHECK and everything that depends on its rows run AFTER the pending security reboot
(W2), in the same boot.

5.3 Effects, in order. Effective uid and gid 0; umask 077; boot identifier equal to the evidence's.
Precheck of everything, before the first creation: every chain walked and held; every destination looked at by
lstat through its parent (children of a directory that does not exist are absent by implication); a directory that
exists is opened and counted; the image inspected by ID; the listing read. Any finding returns REFUSED with the

and entry count, and on the device of the directory it is in: no directory of the layout, the journal root first of

(CREATED_METADATA_MISMATCH), so effects.journal.filesystem_device and mount_point_by_device_change, computed from the
signed rows of the chain the journal hangs from, ARE the filesystem of the journal root: the readback of the README

descriptor; the new directory opened without following; lstat of the name equal to the descriptor; directory,

reference must print the signed ID and list the reference.

5.5 Stated residuals.
  - The docker commands of this operation run with root's own client configuration (as HOSTFACTS_01), not with
    the unit's empty DOCKER_CONFIG. OP_READBACK resolves the same image and tag under the unit's configuration,
    so a difference shows there. This sentence is part of the signed scope statement.
  - A grpid mount gives a new directory its parent's group: caught only after creation (CREATED_METADATA_MISMATCH).
    Default ACLs on a parent were not considered beyond the mode bits.
  - With a data volume root owned by another uid, that owner can rename or remove the empty journal leaf after it
    is created, or swap in another root-owned empty 0700 directory between mkdir and the checks. The producer's
    and reader's own guards on the root, and the catalog binding of device and inode, are the defence. (Any OTHER
    local user is excluded in code: a root writable by others without the sticky bit is refused, 3.9.)
  - docker image tag silently moves an existing tag; the two listings narrow that window, they do not close it.

     O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC, 0644, by dir_fd
  b. unbuffered writes, a gate before each; fsync of the file; fstat: regular, one link, 0:0, exactly 0644, exact
     size, the directory's device
  c. gate; directory proved again; lstat of the temporary: it must still show the inode of the descriptor held,
     with one link (TEMPORARY_REPLACED otherwise, and no name is given to it); link(temporary, final) by dir_fd
     without following (a link cannot replace anything); fsync of the directory
  d. lstat of the temporary must show the inode of the descriptor held; only then unlink; fsync of the directory
Withdrawal. A failure after the temporary exists and before the final name exists (short or failed write, failed
fsync, wrong metadata, failed fstat, failed link other than "exists") withdraws the run's own temporary by the same
identity-proved, gated removal as step d: the row becomes NOT_CREATED with temporary_removed true, the errno of the
failure is kept, and nothing is left for a later operation to remove. The temporary stays, labelled TEMPORARY_ONLY
with temporary_removal_code, when the removal cannot be made: the window expired or a clock went back (no mutating
call after the gate refuses), the directory is no longer the pinned one, the name no longer shows the descriptor
held, or the unlink itself failed. The run is PARTIAL in every one of these cases: it changed the directory.
Residual, stated: link() acts on the name, not on the descriptor held. A root process that swaps the temporary
between the lstat of step c and link() gives the final name to its own object. The run then stops at
LINKED_TEMPORARY_PRESENT with TEMPORARY_REPLACED, is PARTIAL, never complete, and OP_READBACK reports the name
(UNIT_NOT_REGULAR or UNIT_BYTES_MISMATCH). Closing it needs O_TMPFILE and linkat through the descriptor (decision 6).
Then each final name is opened again without following: same inode, one link, 0:0 0644, bytes equal to the signed
render. Complete, fsynced bytes are the only thing that ever stands under a name systemd loads; the temporary
starts with a dot and has no unit suffix (documented systemd behaviour; not observed).
This removal of the run's own temporary is the single removal in the family. The alternative without any removal
is O_TMPFILE plus linkat through /proc/self/fd, which is Linux-only and cannot be tested on the workstation.
Never: a process, a systemctl verb, daemon-reload, a drop-in, an enablement link, an overwrite, chmod, chown, rename.
daemon-reload has NO owner in this family: plan.daemon_reload_owner is a signed name (compared in effects) of the
operation and GO under which the manager is reloaded. The supervisor README still lists the reload in operation 3;
it needs an amendment or the GO must say who reloads.

8. THE secret.env STEP - SPLIT OUT, SPECIFIED, NOT BUILT

Why it is not inside OP_PROVISION:
  - its content cannot be signed. Compose builds the value as postgresql://c3po:<password>@db:5432/c3po, so a
    SHA-256 of the line in any document or receipt is an offline test for the password;
  - it needs a command that asks Docker for an environment entry; every built payload keeps "no template names Env";
  - it depends on a live container; inside OP_PROVISION a stopped or duplicated r2d2-worker would turn the
    directory creation into a partial and spend the GO;
  - the owner signs a different sentence: a second copy of the database URL at rest.
Why it is not built here: the one new command (a Go template that narrows .Config.Env inside the Docker CLI) was
never run on the host, the first design review found a disclosure path in the design, and a payload that moves a
database password as root should not be delivered half-verified in the same pass as four others. The
specification that a build must meet, with both reviews folded in:
  operation GO_WRITE_READER_SECRET_ENV_01, phase WRITE_READER_SECRET_ENV_IN_MEMORY, documents
  WRITE_HOSTOPS_SECRET_ENV_{REQUEST,AUTHORITY,GO,RECEIPT}_V1, the same core, its own source.
  - Target: /etc/c3po-reader/secret.env, 0600 root:root, through the pinned /etc/c3po-reader (rows from the
    OP_PROVISION ledger), by exclusive temporary, fsync, link, removal of the temporary proved by identity.
  - Source: exactly one running container with compose project c3po and service r2d2-worker, selected with the
    reviewed HOSTFACTS argv. One new command: docker container inspect --format
      {{range .Config.Env}}{{$p := split . "="}}{{if eq (index $p 0) "C3PO_DATABASE_URL"}}{{println .}}{{end}}{{end}}
    The CLI prints only the matching entry; stderr is discarded. No fallback that prints the whole environment.
  - Accepted byte shape: one entry line plus the inspector's own newline (println and the per-object newline make
    two); exactly the entry line and one newline is written. The emulator must model both newlines.
  - Shape check in place on one bytearray: key exact, value 1 to 4096 bytes, no NUL, CR or LF. Buffer zeroed in a
    finally (best effort). RLIMIT_CORE 0 and 0 written to /proc/self/coredump_filter before the source command
    (a piped core_pattern ignores the limit; OP_PRECHECK reports whether it is a pipe).
  - NO SIZE ANYWHERE. For secret.env and for its temporary, in every outcome - complete, refusal with a
    pre-existing file, partial, leftover after a crash - the tables hold type, uid, gid, mode, links and booleans
    only (for a leftover at most size_is_zero). Never st_size, a block count, a timestamp, a digest or a length:
    the size of the file minus a constant is the password length. OP_PRECHECK already follows this rule.
  - Canary test: the value, any 8-byte substring, base64, hex, MD5, SHA-1, SHA-256 of the value and of the line,
    the value length, the line length and the file size (with one and with two trailing newlines) appear in no
    receipt of any outcome, no stderr, no exception text, no argv, no command environment and no file but the
    target. Mutants: size emitted in the refusal table; template widened; digest or length emitted; written under
    the final name directly.
  - Receipt booleans: single_line, key_matches, value_within_1_4096, size_equals_bytes_written,
    source_unchanged_during_read.
  - source_unchanged_during_read compares ONLY the one selected field between two reads, never whole inspect rows.
    On the host, HOSTFACTS_01 found 2 of 6 containers changed within 770 ms (CONTAINER_CHANGED, the cause of its
    partial result): a comparison of whole rows would refuse a source whose database URL did not change at all.
Open points for that build: PLAN section 3.3 expects "the same hashes" of secret.env in both gates' receipts,
which contradicts the no-digest rule (proposed replacement: the identity tuple device, inode, mode, links, ctime,
mtime; the plan authors decide); whether /etc is versioned or copied (OP_PRECHECK reports /etc/.git and
/etc/.etckeeper) belongs in the owner's sentence; a crash can leave the 0600 temporary holding the value inside
the 0700 directory.

9. REMOVAL OF A LEFTOVER - NOT BUILT

Nothing in this family removes a pre-existing object. Since revision 2 OP_INSTALL_UNITS withdraws its own
temporary when its file cannot be completed (6.2), so a full disk, a failed write or fsync, wrong metadata or a
failed link no longer leave anything behind. What can still remain after an interrupted OP_INSTALL_UNITS: a
temporary .hostops-*.partial, or a final name that still has two links, after a process death, an expired window,
a clock reversal, a replaced directory, a replaced temporary or a failed removal. systemd does not load the temporary
and a continuation can proceed with it acknowledged, but OP_READBACK reports it (PRIOR_TEMPORARY_PRESENT, or
UNIT_METADATA for two links) and therefore never reaches its success outcome while it exists. Removing it is an
operation of its own (signed name, device and inode; unlink only if the name still shows that identity), with its
own owner sentence. It does not exist. The first design review asked for it to exist before the first write GO is
spent; the signatories decide whether to wait for it or to accept that an interrupted installation is finished by
a hand procedure under a separate authorisation.

12. BINDING PROCEDURE (each step by command; nothing typed from memory)

  1. Reviewer accepts these bytes: SHA256SUMS verified by command; assemble.py re-run changes nothing, wherever the
     reviewer's copy lies. The five blob references of DISPATCH.UNBOUND.json (source, request, authority, go, payload)
     carry the hash of the unbound bytes and a null path, like ssh_key and known_hosts: the binder writes the bound
     files and puts their paths and hashes in the config (step 8), as the binding of HOSTFACTS_01 did, where the
     template's own references were never used. The dispatcher refuses the template as it is (DISPATCH_UNBOUND) and
     would refuse a null path (LOCAL_PATH); it reads each blob by its pinned hash, so no check is weaker for it.
  2. Receipts on record as in section 11, each with its hash; every row copied from a receipt named in evidence.
     A write request cites the OP_PRECHECK receipt its rows come from (the code requires the operation name).
 2b. Before a readback request is written: compute the floor by command from the two terms
     (53687091200 + 603979776 * sessions + allowance) and compare it, by command, with
     items.chains.<chain>.bytes_available_to_non_root_f_bavail of the OP_PRECHECK receipt, <chain> being the one
     effects.journal.filesystem_named_by_chain of the provision names (VAR_LIB under placement A, DATA_VOLUME under
     B): the filesystem the readback measures on the journal root. If the figure is below the floor, do NOT ask for
     the readback signature: the GATE readback would exit 2 with FREE_SPACE_BELOW_FLOOR and spend its GO. In the
     same step read, in that chain's notes, where the device changes: effects.journal.mount_point_by_device_change
     is what the readback request signs as journal_mount_point. On the host as HOSTFACTS_01 read it: placement B
     (54070542336 bytes) is below the floor for every number of sessions, 220528640 short for one, 2636447744 for
     five; placement A meets the five-session floor by 538505326592 bytes: that receipt read /var/lib on the device
     of "/" with the same figures (595212316672 bytes available, section 16). That reading is of the boot of
     2026-10-02; the figure that counts is the one OP_PRECHECK reads on the VAR_LIB chain in the boot of the write,
     and the readback gates the filesystem it finds (JOURNAL_FILESYSTEM_MISMATCH).
  3. Fill the plan. For the units: render with the repository's reference loop (tests/family.py reference_render is
     that loop) and compute rendered_sha256 and rendered_bytes by command, independently of this code.
  4. request: status BOUND, date, windows, host binding, executor_uid 0, evidence; canonical bytes; hash.
  5. effects: compute once with the source's effects_of(plan) offline and READ it: it is what the owner and the GO
     sign. authority and GO carry it literally.
  6. authority (owner, SIGNED, APPROVED, request and payload hashes) -> hash -> GO (SIGNED, GO, three hashes,
     transport_binding with the four runtime pins and the command pin, claim_root_identity, the constant
     scope_statement, success_criterion).

     latest_start = not_after - 80 s.
  8. Final payload with launcher_stdin.build; config with its pins and the paths of the five bound blobs (null in
     the template); publication proof.
  9. Dry validation: the source's authenticate() on the bound bytes with the target uid injected, and perform()

 10. Publish the hashes of the final payload and of the config. Prepare -> publication -> resume, once.
