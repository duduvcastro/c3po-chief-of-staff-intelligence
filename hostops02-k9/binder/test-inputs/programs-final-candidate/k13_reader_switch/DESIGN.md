## 0. In one paragraph

One payload, `GO_WRITE_HOSTOPS02_K13_READER_SWITCH_01`, three modes signed in the plan. **ACTIVATE** (PLAN row M6, A2 M6-1/M6-2/M6-s): every guard of RDR operation 4 that this core can express is read first; then `/etc/c3po-reader/activation.env` is created exclusively with its two constant lines (sha256 `2053f3f6…f611b`, recomputed by command and by a test), or, when it already holds exactly those bytes with 0:0 0600 one link, accepted (reconcile); then `systemctl enable --now c3po-reader.timer` and `systemctl start --no-block c3po-reader.service`, each settled by a readback in the run. **RESTART** (A2 RST, RDR 7): the same guards with the activation file required, then `systemctl reset-failed` and `systemctl start --no-block` of the service. **DEACTIVATE** (PLAN X1, RDR 8): the states of the two units as read (revision 2: no file is read and nothing about them is required), then `systemctl disable --now c3po-reader.timer` and `systemctl stop --no-block c3po-reader.service`; nothing is deleted. `WRITES_ALLOWED=True`, `ACTIVATION_ALLOWED=True`, `DATE_CLASS='WRITE_SESSIONS'` (10-05 … 10-10 UTC), gate ≤ 900 s, `SUCCESS_IN_TEMPLATE=False`. Parts: core, runner, docker, parents, files. Tools: systemctl and docker (trusted absolute binaries), no shell.

## 1. Outcomes

| Mode | Success (exit 0) | Meaning |
|---|---|---|
| ACTIVATE | `RETURNED_REQUIRES_LIVENESS_READBACK` | file present with the constant bytes; timer read back `enabled` + `active`; service `active` or `activating`. K13r (mode LIVE) must follow (PLAN M7) |
| RESTART | `RESTART_RETURNED_REQUIRES_LIVENESS_READBACK` | reset-failed returned 0 and the service is no longer `failed`; service `active`/`activating` |
| DEACTIVATE | `DEACTIVATED_REQUIRES_STOP_READBACK` | timer `disabled` + `inactive`; service not `active`/`activating`/`reloading` (with `--no-block` it is usually `deactivating`). K13r mode STOPPED must follow (it requires `inactive` or `failed`) |

`REFUSED_NOTHING_CHANGED` (exit 1) only while `state.clean()`; `PARTIAL_SWITCH_STATE_REQUIRES_READBACK` (exit 2) otherwise. `activation_performed` = True when a switch read back DONE, None when one is uncertain, else False. `daemon_reload_performed` = True only when `enable --now` / `disable --now` exited 0 (systemd documents that both reload the manager unless `--no-reload`; not observed on the host), None when such a switch started and did not return, or returned non-zero and is DONE or UNKNOWN, else False. Each switch carries `changed` (the components it acts on read differently after the run than before it; None when not attributable) and the receipt `switches_changed_state` (True / False / None): a reconcile of a running reader completes with `false` there, which is RDR's "the starts then change nothing and the receipt says so".

## 3. Effects and how each is settled

| Mode | Order | Class |
|---|---|---|
| ACTIVATE | `create_file(activation.env, 0600)` only if absent → `systemctl enable --now c3po-reader.timer` → `systemctl start --no-block c3po-reader.service` | SWITCH 30 s, QUICK 8 s |
| RESTART | `systemctl reset-failed c3po-reader.service` → `systemctl start --no-block c3po-reader.service` | QUICK, QUICK |
| DEACTIVATE | `systemctl disable --now c3po-reader.timer` → `systemctl stop --no-block c3po-reader.service` | SWITCH, QUICK |

The run stops at the first switch that did not start, did not return, or returned non-zero. After the switches: `is-enabled` and `show` of both units (one readback), then each switch that returned is settled: DONE when the state it must reach is read (enable: `enabled`+`active`; start: `active`/`activating`; reset-failed: exit 0 and not `failed`; disable: `disabled`+`inactive`; stop: not active); FAILED_NOTHING_CHANGED when it exited non-zero and the components it changes (timer word and state for enable/disable, service state for the others) read as before the run — and, for `enable --now` / `disable --now`, only when the word read before was not already the target word (revision 2: when it was, the failure may have come after the manager reloaded, so nothing read proves nothing changed); UNKNOWN otherwise (and always when the readback failed). Then the file: `readback_file` of the created one, or the constant one read again (`ACTIVATION_ENV_CHANGED`). Then, ACTIVATE/RESTART, a fact that never gates: the `c3po-reader` container if it already exists (ID, state, start instant, image equal to the pin, restarts). Complete only when every switch is DONE and the file is as required.

Known consequence: in RESTART a reset-failed that changed the service followed by a failed start is UNKNOWN for the start (no read between the two switches).

## 4. Budget (CORE section 4)

`effects_budget` sums the class seconds of the effect rows. SWITCH (30 s) for every systemctl effect would need 30 + 30 + 30 + 4 = 94 s for the three calls the design brief named (enable, start timer, start service): impossible in 60 s. The frozen assembler does not constrain the class of a systemctl EFFECT row, so: `enable --now` (one call for "enable" + "start timer", RDR's order kept) and `disable --now` keep **SWITCH** (they reload the manager: the core's table names that class for it); `start --no-block`, `stop --no-block` and `reset-failed` are **QUICK** (8 s): `--no-block` returns once the job is queued, `reset-failed` clears a state. Figures: ACTIVATE 30 + 8 + 4 + 3 (file) = 45 s must be left when the precheck ends; DEACTIVATE 45; RESTART 8 + 8 + 4 + 3 = 23. The precheck therefore has about 15 s on a normal host for ACTIVATE (about 20 commands; one per running container for the scan). A QUICK switch killed at 8 s is UNKNOWN and the run PARTIAL (rule 4.1), never silent. Tested at the edges with `family.Budget` (45 s passes, 44.5 s refuses; 23/22.5 for RESTART).

## 5. Deviations from RDR and from the brief, with reasons

1. **`docker top` is not expressible — a SIGNED GAP: it needs the owner's or Codex's explicit acceptance before any GO (Q-4).** The frozen assembler admits a docker row as READ only for `image inspect`, `container inspect`, `ps`, `info`, `version`, `image ls`, `compose config`; `top` would have to be an EFFECT row (counted as a mutation, illegal in K13r). Replacement: the main command (`.Path`/`.Args`) of every running/paused/restarting container through a fixed inspect template, plus the count of `.ExecIDs`. **Gap:** a reader started by `docker exec` inside another container (RDR's reason for `docker top`) is NOT detected; exec sessions are counted, not judged (health checks create them too). Also a child process of a container's main process is not seen.
2. **`secret.env` by metadata only** (lstat: regular, 0:0, 0600, one link). RDR asks that it "has its shape" (one line, name `C3PO_DATABASE_URL`, equal to the worker's). Reading it would put secret bytes in this process; that check belongs to A7/K3's readback. Never opened, read, hashed or sized here.
3. **No `findmnt`.** RDR compares the `findmnt` line (mount point, source, fstype) of the journal root. This core has no such tool; device numbers come from the signed rows and the held descriptors (the journal device must differ from the data volume's, and from the bytes), the free space from `fstatvfs` on the held root. Mount source and filesystem type are not checked.
4. **No "receipt UNCERTAIN written and synced before the effects".** The family's receipts are returned by the launcher, not written by the source; the dispatcher's claim and the transport play that role (UNCERTAIN = exit 3).
5. **`enable --now` instead of `enable` then `start` of the timer** (section 4). Same order of effects, one call.
6. **`start --no-block` / `stop --no-block`** instead of blocking calls (PLAN M6 already says `--no-block`). RDR 8's readback "container absent, last notice STOPPED" is therefore K13r's (mode STOPPED), not this run's.
7. **The release check reads the release file** from the data volume (0:0 0600) and compares it with the signed hash and with `pins.env`'s two release lines; RDR says "the installed release bytes hash to the pin of pins.env". The capacity configuration hash of `pins.env` is not re-derived (the capacity tree is not walked).
8. **Window in UTC with New York = UTC−4** for the whole epoch (EDT ends 2026-11-01; no early close among the five sessions). DEACTIVATE has no launch window (X1 runs after the close).
9. **`LoadState=loaded` is required** before any switch; the units were installed without `daemon-reload` (B2) and `systemctl show` makes the manager load a new unit from disk (systemd 255). If the manager had cached the unit as `not-found` earlier, ACTIVATE refuses (`READER_UNIT_NOT_LOADED`) although `enable --now` would reload it (Q-3).
10. **The `c3po-reader` container may not exist yet** when ACTIVATE completes (`--no-block`); the receipt carries it as a fact when present. Its ID and start instant are K13r's to establish.

## 6. What never happens

No `docker run/exec/stop/rm/logs/top`, no `daemon-reload` of its own, no drop-in, no write except `activation.env` (exclusive temporary, link, removal of the own temporary), no overwrite/chmod/chown/rename/truncate, no environment value, no container command line, no log line in the receipt, no wait for a unit to settle, no retry.
