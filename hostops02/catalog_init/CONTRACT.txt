6. WHAT A RECEIPT MEANS FOR THE GATES

  KNOWN_COMPLETE, mode REAL, outcome CATALOG_READY_VERIFIED
      Operation 4b is done on that root. It is the receipt the activation gate asks for ("Catalog (from operation
      4b)", README line 575) and the condition of the unit installation in the plan (A9 before B1). The readback of
      operation 4 (hostops01 OP_READBACK) signs catalog{expected INITIALISED, receipt_sha256, device, inode} from it:
      receipt_sha256 = this receipt's metadata_sha256; device and inode = script_line.device and script_line.inode
      (in a complete receipt equal to journal_root.device and journal_root.inode). The epoch of the receipt
      (effects.epoch) is compared by command with the "epoch" field of the release bytes once the release is signed.
  KNOWN_COMPLETE, mode REHEARSAL, outcome REHEARSAL_CATALOG_READY_VERIFIED
      The same bytes, argv, script, image and engine created and verified a catalog on the filesystem of the real
      root; the docker CLI of the host left nothing in the directory it was given, across its four commands; the real
      root and the unit's configuration directory were as REAL requires them at that instant, and no docker command
      ran under the unit's directory. It allows the REAL request to be dispatched. It is never the 4b receipt and no
      gate may cite it as such: its mode, path, epoch and outcome say so.
  KNOWN_REFUSAL (exit 1)
      Nothing was created and no container was started; where docker reads ran (REAL), the directory they were given
      was counted empty afterwards. The signature is spent; the root is untouched and usable under a new request with
      a new signature. One limit, the frozen core's: a run interrupted by something that is not an ordinary failure
      (an interrupt signal that Python turns into an exception) is filed by the core as a refusal of phase
      BEFORE_ANY_EFFECT without that count. It is exact once the rehearsal has shown that the CLI writes nothing.
  KNOWN_PARTIAL (exit 2): read root_verdict.
      NOT_TO_BE_USED_AGAIN: the README's rule. REAL: a new leaf under a new authorisation (hostops01 provision, group
      JOURNAL_LEAF) and a new 4b request on it, two signatures, with the journal pair of every later operation
      changed. REHEARSAL: a finding; production is untouched; another rehearsal needs another throwaway name;
      `directories` says which of the two throwaway directories exist.
      CATALOG_VERIFIED_WITH_FINDINGS: the root holds the verified catalog; the run is still not complete. Whether the
      next operation may follow is a written reading of the signatories after a read-only look at the containers
      and at the configuration directory; the gate readback reads the catalog again in any case. With the code
      ENGINE_STATUS_AFTER_A_VERIFIED_CATALOG the finding is docker's own exit status (run.returncode) beside a
      verified catalog: the README's "--rm can surface a clean exit as 125".
      UNTOUCHED_NO_CONTAINER_STARTED (REAL, phase PRECHECK, the two DOCKER_CONFIG_DIRECTORY_..._AFTER_THE_READS
      codes): the journal root is untouched and usable. The unit's configuration directory is not: until it is empty
      again every run of these bytes refuses at its first look, and the gate readback reports DOCKER_CONFIG_NOT_EMPTY.
      Emptying it is a removal, which no payload of either family performs: a separate authorisation and new bytes.
      The rehearsal exists so that this receipt cannot be the first news of a CLI that writes.
      No root_verdict (outcome PARTIAL_STATE_UNKNOWN_ROOT_NOT_TO_BE_USED_AGAIN, or a receipt reduced to its minimum):
      as NOT_TO_BE_USED_AGAIN, and a read-only look records what is there.
  Reading a failed run: DESIGN.md section 4, "Reading a failed run" (125 with no line; 126 and 127; a refusal of the
      script whose code is NOT_A_CONSTANT_CODE, matched offline by the hash of the line).
  UNCERTAIN (no receipt, or one the dispatcher cannot accept)
      REAL: the root is treated as NOT_TO_BE_USED_AGAIN: without a receipt a run that never started cannot be told
